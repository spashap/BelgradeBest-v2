TOMORROW: node scripts\submit-to-bing.mjs --prefix=/glossary
(32 URLs, fits the quota; resubmitting an already-sent URL is harmless.)

TOOL CHANGE: submit-to-bing.mjs --urls=<file>

One URL per line, order preserved, entries absent from the sitemap dropped
with a notice. --prefix could not express this set: a prefix matches
everything beneath it, so "/expo-2027" cannot mean the hub alone, and --all
would have spent the cap on glossary terms in alphabetical order.

The crawl-status check that would normally choose the set (GetUrlInfo per
URL) was unusable - Bing answered 400 ThrottleHost for every call, and the
script's four retries turn that into ~20s per URL. GetPageStats, which is
site-level and not throttled, stood in for it. That over-includes pages Bing
crawled but never showed, which costs quota, not accuracy.

OPERATIONAL NOTE

Bing GetUrlInfo throttles under parallel calls and answers 400 ThrottleHost,
which silently turns a concurrent crawl-coverage sweep into false "never
crawled" results. Use the script's 1/sec pacing, one prefix at a time, and
run it from PowerShell - or with MSYS_NO_PATHCONV=1 under Git Bash, which
otherwise rewrites --prefix=/de into a Windows path.
